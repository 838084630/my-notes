# 📖AWS 学習ノート

## セキュリティ・コンプライアンス

### セキュリティ監視サービス

#### GuardDuty、Inspector、Macie

| サービス      | 監視対象          |
| ----------- | --------------- |
| GuardDuty   | 攻撃/異常行為     |
| Inspector   | 脆弱性            |
| Macie       | 機密データ        |

#### AWS Shield
- DDoS攻撃からの保護に特化したサービス
- Shield Advanced：主にDDoS攻撃対策に特化

#### AWS WAF（Web Application Firewall）
- クロスサイトスクリプティングやSQLインジェクションなどの脆弱性を突く攻撃からWebアプリケーションを保護

#### AWS Network Firewall
- VPC向けのファイアウォール機能を提供するマネージドサービス
- ネットワークトラフィックの監視及び制御がメイン

### 統合管理サービス

#### Amazon Security Hub
- AWSのセキュリティサービス（GuardDuty、Inspector、Macieなど）やサードパーティ製ツールからアラートなどの検出情報を自動収集
- 統合的に可視化・管理

#### AWS Control Tower
- AWSのベストプラクティスに基づいたセキュアなマルチアカウント環境（ランディングゾーン）のセットアップを自動化

#### AWS Firewall Manager
- AWS Organizations環境で組織全体のファイアウォールのルールを一元的に設定・管理
- 組織内のAWSアカウントに対して一貫したセキュリティルールを統一的に適用

### アクセス管理

#### AWS IAM Identity Center
- 複数のAWSアカウントやSaaSアプリケーションへのアクセスを一元管理

#### AWS CloudHSM
- 専用のハードウェアデバイスを用いて暗号化鍵を生成・管理

#### ACL（Access Control List）
- AWSアカウント単位でアクセス権限を設定
- 他のAWSアカウントに対してS3バケットやオブジェクトへの読み取りまたは書き込みを許可

### 監視・監査

#### AWS CloudTrail
- AWSサービスに対して「いつ」「誰によって」「どのような操作が行われたのか」を記録・保存
- 監視対象イベント：
  - 管理イベント：ユーザーのログイン、EC2インスタンスの作成など
  - データイベント：S3上のオブジェクトの操作、Lambda関数の実行
  - インサイトイベント：通常と異なる操作（書き込みAPIの呼び出し）

#### AWS Trusted Advisor
- AWSサービスの利用状況をベストプラクティスと照合
- 改善のためのレコメンデーションを提示

## コンピュート

### EC2（Elastic Compute Cloud）

#### インスタンスタイプ

**インスタンスストア**
- EC2インスタンスから利用できる揮発性のブロックストレージ
- ホストコンピュータに物理的に割り当てられたディスク上にあり、非常に高いパフォーマンス
- インスタンスに障害が発生したり停止・終了するとデータが失われる

**Dedicated Hosts（専有ホスト）**
- 他のEC2インスタンスとは分離された専用ハードウェアで利用可能
- CPU、メモリ、ストレージ、ENIの完全な分離が実現可能
- 高価格でコスト効率性の課題あり

### Amazon ECS（Elastic Container Service）

#### 主要要素
- **クラスター**：ECSで管理する基本的な単位
- **タスク**：ECSで管理するコンテナの実行単位
- **サービス**：タスクのライフサイクル管理
- **タスク定義**：コンテナイメージ、CPU、メモリのスペック、タスクロールなどを定義
- **タスクロール（taskRoleArn）**：コンテナが他のAWSサービスを利用する際に設定するアクセス権限（IAMロール）

### AWS Elastic Beanstalk

- アプリケーションが動作する定番の構成を提供
- 定番構成の中からアプリケーションの実行環境に適したものを選択
- 数クリックで環境（インフラ）を作成可能
- 環境の作成後にアプリケーションをアップロードしてデプロイ

### AWS Lambda

**実行時間制限**
- 1回につき最長15分という制限あり
- 大量のデータ転送などの長時間処理には不適切

**Lambda@Edge**
- CloudFrontと連携して動作
- ストックフォトサービスでの透かし（ウォーターマーク）付与などのユースケースがある

## ストレージ

### Amazon S3（Simple Storage Service）

#### アクセス制御

**S3のゲートウェイVPCエンドポイント**
- VPC内のリソースがプライベートネットワーク経由でS3バケットに接続するための機能

**CloudFrontのOAC（Origin Access Control）**
- S3バケット内のコンテンツへのアクセスをCloudFront経由でのアクセスに限定
- クライアントからS3バケットへ直接アクセスされないようにする
- オリジンサーバーのデータを保護

#### データ転送・レプリケーション

**S3 Transfer Acceleration**
- ユーザーとS3バケット間のデータ転送を高速化する機能
- HTTP/HTTPSでの通信をサポート
- SFTPはサポートしていない

**S3クロスリージョンレプリケーション**
- データを複数リージョンで同期
- どのリージョンでも最新のデータにアクセス可能

**マルチリージョンアクセスポイント**
- 自動的に1つのグローバルなアクセスポイント（グローバルエンドポイント）を生成
- クライアントはグローバルエンドポイントを通じて複数リージョンのバケットにアクセス可能

**S3イベント通知**
- 注：同一条件の通知を複数の宛先に送ることはできない

### Amazon EFS（Elastic File System）

- NFS（Network File System）プロトコルをサポートするファイルストレージサービス
- 主にLinuxを含むUNIX系のサーバーで使用
- Windows EC2インスタンスからのマウントはサポートされていない

### Amazon FSx

#### FSx for Windows File Server
- SMBプロトコルを使用してWindows Server上に構築されたファイルシステムを提供
- フルマネージドのファイルストレージサービス
- SMBはLinuxからもクライアントを用いてマウント可能

#### FSx for Lustre
- 高性能計算（HPC）向けの高スループットなファイルシステム
- NFSはサポートするがSMBは非対応

#### FSx for NetApp ONTAP
- NetApp SnapMirror：標準搭載されたデータレプリケーション機能
- スナップショットを利用した差分同期方式により、継続的かつ自動的なレプリケーション

### AWS Storage Gateway

- オンプレミスからAWSのストレージサービスへの高速かつセキュアなアクセス

#### ファイルゲートウェイ
- オンプレミスからNFSやSMBを使用してS3バケットまたはFSx for Windowsファイルサーバーへアクセス

#### ボリュームゲートウェイ
- S3をiSCSI接続のブロックストレージボリュームとして利用
- 「キャッシュ型」と「保管型」の2つのタイプがある
- オンプレミスのアプリケーションサーバーからiSCSIデバイスとして利用可能

#### S3ファイルゲートウェイ
- NFSとSMBをサポート
- SFTPはサポートしていない

## データベース・キャッシュ

### Amazon DynamoDB

#### テーブルクラス
- **標準テーブルクラス**：頻繁にアクセスされるデータに適している
- **標準IAテーブルクラス**：アクセス頻度の低いデータに適している

#### 課金モード

**オンデマンドモード**
- 読み書きリクエスト数に応じた従量課金
- アクセス頻度が予測不能なワークロードに適している

**プロビジョンドモード**
- 事前に1秒間あたりの読み書き量（キャパシティユニット）を設定
- アクセス頻度が予測できるワークロードに適している

#### DynamoDB Streams
- テーブルに対して行われた直近の24時間の変更（追加、更新、削除）をログに保存
- ストリームを参照することによっていつ誰がどのようにテーブルを更新したかがわかる

#### ACID特性
- 原子性（Atomicity）
- 一貫性（Consistency）
- 独立性（Isolation）
- 耐久性（Durability）

### Amazon ElastiCache

#### Memcached型
- データストレージにメモリ（RAM）を使用するインメモリデータストア
- セッション情報の一時保管には適している
- マルチAZや永続保持の機能がない
- ファイルシステムとしてネイティブにマウントできない

#### Redis型
- マルチAZに対応
- データの永続保持が可能

### Amazon Redshift

- ペタバイト級のデータを扱えるデータウェアハウス
- 大規模データの高速クエリ処理が可能
- データ分析などに利用

## メッセージング・イベント

### Amazon SQS（Simple Queue Service）

#### キューの機能

**ロングポーリング**
- SQSキューのメッセージが空である場合に設定された時間待機する機能

**遅延キュー**
- メッセージをSQSキューに追加した後、指定時間が経ってからメッセージを配信できる状態にする

**可視性タイムアウト**
- 他のインスタンスがメッセージを受信可能になるまでの猶予時間
- この値を増やすことでメッセージの重複処理を排除できる

**デッドレターキュー**
- エラーが一定の回数に達したメッセージを隔離するためのキュー
- SNSがメッセージ配信に失敗した場合、配信不能メッセージの送信先としても利用可能

#### FIFO
- FIFOトピック：メッセージが順序付けられてAmazon SQSのFIFOキューへ配信される

### Amazon SNS（Simple Notification Service）

#### デッドレターキュー
- SNSがメッセージ配信に失敗した場合、配信不能メッセージの送信先として利用可能

#### FIFOトピック
- メッセージが順序付けられてAmazon SQSのFIFOキューへ配信

### Amazon EventBridge

#### EventBridge Pipes
- 主に1つのソースから1つのターゲットへイベントを連携する用途に適した機能

#### イベントバス
- AWSサービスや独自のアプリケーション、SaaSプロバイダーなどから送られたイベントを受け取り
- 条件に応じて適切な送信先へ振り分けるための仕組み

## ネットワーク・コンテンツ配信

### Amazon CloudFront

- AWS上で動作する安全で高速なコンテンツ配信ネットワーク
- 主にWebコンテンツに対してエッジロケーションのキャッシュを利用して低遅延の通信を実現
- 静的コンテンツと動的コンテンツともに低遅延で配信可能
- HTTP/HTTPSのみをサポート（TCP、UDP通信には対応していない）
- リアルタイムで更新され続けるデータ（例：株価）には向いていない

#### CloudFront OAC（Origin Access Control）
- S3バケット内のコンテンツへのアクセスをCloudFront経由に限定
- クライアントからS3への直接アクセスを制限

#### Lambda@Edge
- CloudFrontと連携
- ストックフォトサービスでの透かし（ウォーターマーク）付与などのユースケースがある

### AWS Global Accelerator

- ユーザーを最寄りのエッジに接続
- AWSバックボーンを使ってエンドポイントへ転送
- 動的トラフィックの遅延を改善できる場合がある
- ネットワーク状況やエンドポイントの状態を基に最適なリージョンを自動的に選択
- 地理的に分散したIoTデバイスであっても低レイテンシーで処理システムに接続可能
- 対象リージョンに障害が発生した場合でも、健全な別リージョンのNLBへ自動的にトラフィックを切り替え可能
- 2つの固定パブリックIPアドレスを保有
- エンドポイントとして設定可能：ALB、NLB、EC2インスタンス、Elastic IPアドレス
- S3バケットはエンドポイントとして設定できない
- 株価配信サービスやチャットアプリケーション、オンラインゲームなど常に更新され続けるデータの利用に適している

### S3 Transfer Acceleration

- ユーザーとS3バケット間のインターネット経由のデータ転送を高速化
- HTTP/HTTPSでの通信をサポート

### Amazon API Gateway

- HTTP/HTTPSでの通信をサポート
- SFTPはサポートしていない
- REST API、HTTP API、WebSocket APIがある
- キャッシュ機能はREST APIでのみ利用可能

### Amazon Route 53

#### Route 53リゾルバー
- AWS内で実行されているリソースと、オンプレミスのデータセンターや他のクラウド環境との間でDNSクエリのルーティングと応答が可能
- 内部トラフィックの管理に有効
- 外部向けのDNSパフォーマンス問題には対応していない

#### レイテンシーベースルーティング
- 利用者を最も応答の速いリージョンへ誘導するための仕組み

## バックアップ・災害復旧

### AWS Backup

- AWSリソースのバックアップを一元管理するフルマネージドサービス
- EC2インスタンス、EFSファイルシステム、RDSデータベースなど多くのAWSリソースを対象
- EC2インスタンスをバックアップ対象として指定可能
- バックアップにはアタッチされたEBSボリューム、起動設定、インスタンス構成情報も含める
- 柔軟なバックアッププランを作成可能

### Amazon Data Lifecycle Manager

- EC2のEBSボリュームやAMIのスナップショット取得と保持管理に特化
- EBSスナップショットのライフサイクル管理やクロスリージョンコピーに対応
- EBSボリュームのスナップショットのみを保護（EC2インスタンス単位でのバックアップとは異なる）
- 起動設定やインスタンス構成情報を含めて保護する要件には不十分

### AWS Elastic Disaster Recovery

- オンプレミスや他のクラウド上で動作しているサーバーやアプリケーションをAWSに継続的にレプリケーション
- 障害や災害発生時にシステムを迅速かつ低ダウンタイムで復旧可能な災害復旧（DR）サービス

### Amazon Application Recovery Controller

- AWS上のアプリケーションの回復性を高めるためのサービス
- 複数リージョンにまたがる構成を1つの復旧対象としてまとめて管理
- どのリージョンへトラフィックを向けるかをシンプルな制御で切り替え可能

## 運用・監視

### AWS Systems Manager

- 複数のAWSリソースをグループ化
- グループ内リソースの運用データの一元化や運用タスクの自動化などが可能

#### AWS Systems Manager Automation
- AWSリソースへの操作をランブックに従って自動的に実行

### Auto Scaling

#### ライフサイクルフック
- スケーリング発生によるEC2インスタンスの起動または終了時に任意の処理を実行する機能
- スケールアウトによって新たに追加したインスタンスに初期化スクリプトを実行
- スケールインによって終了するインスタンスのログを収集・退避
- 注：特定のスケジュール（例：休日）に基づいてインスタンスを停止・終了させる機能はない

### AWS CloudWatch

- 運用監視

### AWS X-Ray

- アプリケーションの動作に関するデータを収集・分析

### AWS Fault Injection Service

- 障害を意図的に発生させてシステムの耐障害性を検証

## データ分析・処理

### AWS Glue

- ETL（Extract：抽出、Transform：変換、Load：書き出し）サービス
- 複数のデータソースからデータを抽出
- 統合・変換したデータをターゲットへ格納
- バッチ処理に適しており、リアルタイムのデータ処理には適していない
- Amazon Data Firehoseはリアルタイムデータの受信に適している

### Amazon Managed Service for Apache Flink

- ストリーミングデータ処理に利用可能
- Flinkのチェックポイント：Flinkアプリケーションの状態を耐障害化し、障害時に復元するための仕組み

### Amazon Kinesis Data Streams

#### 拡張ファンアウト
- コンシューマーが専用のデータスループットを確保できる仕組み

## 共通パターン・用語

### エクスポネンシャルバックオフ

- リクエストが失敗した際にクライアント側がすぐに再試行しない
- 試行回数に応じて再試行間隔を指数的に延ばして再試行（例：1秒→2秒→4秒→8秒…）
- 成功率を高める手法

### Canaryリリース

- 新しいバージョンのAPIを段階的にリリースする方法

### キャッシング戦略

- CloudFrontはエッジロケーションのキャッシュから配信することで効率的に低遅延で配信可能
- ニュースコンテンツを配信するWebサイトなどに適している
